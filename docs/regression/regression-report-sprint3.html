How the AI is tested

The real detection graph runs end to end: the lead plans, the three specialists run in parallel and call the real tools, the lead reviews, asks for at most one second look, and the report is merged. Only Claude's replies are scripted.

  • What it proves: the fraud checks catch each injected anomaly, and the graph turns their findings into the right verdict, specialists list, second look and combined report.
  • What it doesn't: whether Claude picks the right tools and ratings on the real documents. That's the manual live run at the end of each sprint.
  • Test documents: generated in the test, each carrying its case's injected anomaly, because the Sprint 3 PDFs aren't in the repository. Case match and the misspelt company name use real cases saved from Supabase (GLDB-02, GLDB-16).
  • No credits spent: the tests block any real Claude request, even with a real API key in .env.

Needs a decision

  • FD-025 wording. The spelling check skips company names on purpose; a misspelt one is caught by the company-name check instead. So "SHIPING" is flagged as a company-name mismatch, not under Spelling, as the test case expects.
  • FD-016 wording. Every specialist now reviews every document, so "each skipped specialist with its reason" is always an empty list.
